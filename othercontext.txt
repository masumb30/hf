# NEXT 16 ROUTE HANDLER SIGNATURE (CRITICAL)
Dynamic params are a Promise — always await them:

export async function GET(
  req: Request,
  { params }: { params: Promise<{ id: string }> }
) {
  const { id } = await params;
}

# CONVENTIONS
- API folder: app/api/**
- Each route.ts exports one handler per HTTP method (GET, POST, PATCH, PUT, DELETE).
- Folder naming: kebab-case for multi-word; plain lowercase for single word.
- No version prefix.
- Auth namespace: api/auth/me, api/auth/sign-in, api/auth/sign-up, api/auth/sign-out.
- Self-scoped views use /me singleton: attendance/me, leave/me, notifications/me, dashboard/me.
- State transitions get their own sub-route with PATCH (e.g., users/[id]/deactivate).
- Plain field edits use PATCH on the base resource.
- Search/filter via query params on list endpoints (?q=&role=&dept=&status=).
- Conversation creation: single POST at conversations/route.ts with type-discriminated body.
- Dashboard: role-scoped summary routes + granular concern routes.
- Uploads: Route Handlers with multipart/form-data.
- Audit logs: Admin only.

# GLOBAL RULES (APPLY TO EVERY ENDPOINT)
1. Must be authenticated (except sign-in, sign-up).
2. Input validated (Zod).
3. Authorization enforced SERVER-SIDE — not just UI.
4. deletedAt != null users cannot authenticate or act.
5. deactivatedAt != null users cannot act; HR/Admin can still read their historical records.
6. Soft-deleted records excluded from default lists.
7. Audit log writes happen in the SAME transaction as the mutation.
8. Attachment access requires conversation participation — storageKey alone is never enough.

# ROLES
- ADMIN
- HR_MANAGER
- EMPLOYEE

# ROLE LEGEND IN ROUTE MAP
- (admin)          = Admin only
- (admin, hr)      = Admin + HR Manager
- (admin, hr, employee) = all authenticated roles
- (self)           = acting user operating on own record (relationship check on top of role)
- (participant)    = active participant of the conversation
- (public)         = no auth required
- (admin, hr, dept_head) = including department head of sender department

# LEAVE REVIEW RULE (OPTION B)
Helper: canReviewLeave(actor, target)
Returns true only when ALL hold:
1. actor.id !== target.id
2. target.status === ACTIVE
3. target.role === EMPLOYEE   → actor.role ∈ { ADMIN, HR_MANAGER }
4. target.role === HR_MANAGER → actor.role === ADMIN
5. target.role === ADMIN      → actor.role === ADMIN AND actor.id !== target.id

Single-admin edge case: Admin leave request stays PENDING indefinitely (documented assumption).

# PENDING LEAVE SCOPING
- Admin GET /leave/pending → sees ALL pending.
- HR    GET /leave/pending → sees ONLY EMPLOYEE-originated pending (HR-actionable).

# DIRECT MESSAGE PRIVACY
- DIRECT conversations: only the two users in dedupeKey.
- Admin/HR get NO bypass to DIRECT conversations.
- ORGANIZATIONAL conversations: participants + upward hierarchy (via Department.path) for departmental comms.

# SEED DATA REQUIRED
- 2 Admins
- 2 HR Managers
- ~4 Employees
- Department tree (Organization → Human Resources → Recruitment / Training / Employee Welfare; Operations → Field Operations → Maintenance; Finance → Accounts / Audit)
- Sample attendance, leaves, conversations.

# PRISMA SCHEMA SUMMARY (for reference)
# ============================================================

Models: User, Department, Attendance, LeaveRequest, Conversation, ConversationParticipant, Message, Attachment, Notification, AuditLog.

Enums:
  Role              ADMIN | HR_MANAGER | EMPLOYEE
  EmploymentStatus  ACTIVE | INACTIVE | TERMINATED
  LeaveStatus       PENDING | APPROVED | REJECTED | CANCELLED
  LeaveType         ANNUAL | SICK | UNPAID | MATERNITY | PATERNITY | COMPASSIONATE | OTHER
  ConversationType  DIRECT | ORGANIZATIONAL

Key fields:
  User:        deactivatedAt (soft), deletedAt (soft), departmentId, role, status
  Department:  parentId, path (materialized), headId, children
  Attendance:  (userId, date) daily unique; clockIn, clockOut
  LeaveRequest: userId, reviewerId, status, reviewNote, reviewedAt
  Conversation: type, dedupeKey (DIRECT only, sorted user IDs "a:b"), lastMessageAt
  ConversationParticipant: userId OR departmentId (exactly one), isActive, lastReadAt
  Message:     conversationId, senderId, content?, editedAt, deletedAt
  Attachment:  messageId, fileName, mimeType, fileSize, storageKey (opaque)
  Notification: userId, type, payload Json, readAt
  AuditLog:    actorId?, action, entityType, entityId, metadata Json

# AMBIGUOUS ITEMS (INTERPRETED — DOCUMENT IN README)
# ============================================================
- Public sign-up creates EMPLOYEE, ACTIVE, no department.
- updateUser allows self, but self cannot change role/status/departmentId.
- updateProfileImage is self-only.
- getMyAttendanceStats as a separate endpoint.
- Department read access for employees (flat list, tree, by id).
- removeEmployeeFromDepartment as DELETE on users/[id]/department.
- removeDepartmentHead as DELETE on departments/[id]/head.
- cancelLeaveRequest allowed only on PENDING.
- Conversation POST role gate varies by type.
- editMessage / deleteMessage with no time limit.
- previewAttachment as a separate endpoint.
- deleteNotification allowed.
- HR dashboard pending count = HR-actionable only.
